# Slides · 簡報

Slides serve the lesson plan; write the plan first (unless you're reverse-engineering a plan from an existing deck). Deliver a **slide plan** (`templates/slide-skeleton.md`) and, if the designer wants, build the deck in their tool from their template.

## Page structure comes from the designer
Ask how they want each part laid out before drafting; designers often have a clear pattern in mind. Common patterns to offer if they don't:
- **Two pages per item:** a story/context page, then a real-world page (photo of the actual place or thing) with the key word and sentence.
- **Two pages per word:** a picture-only page (kids guess), then the same picture labelled in English + 中文.
- **A continuous story told in pictures:** consecutive illustrations, like a picture book (the character arrives at each stop), ending with one page that puts all the pieces together (e.g. the full journey map).
- **One page per key verb or pattern**, briefly showing the link between the idea and the word before practising it.

There's no fixed page count — it follows the structure and the time available. Younger groups: fewer ideas, bigger pictures, more repetition.

## Always include
- Title page (EN + 中文, level)
- Warm-up question tied to kids' lives
- Series lessons only: a short review bridge to the previous lesson
- Optional video marked "skip if short on time"
- A review round before practice
- A clear hand-over page for each practice block, with rules on screen if helpful

If the lesson has a localisation slot (optional, place-based content only): examples from several regions on the slide; the lesson plan tells the volunteer to talk only about the nearest one.

## Design principles
1. One idea per slide; big images over text.
2. Bilingual, short English; sentence patterns as fill-in-the-blank.
3. Same word forms as the lesson plan, cards and worksheet.
4. No decorative images unrelated to the content; note sources for photos and maps.
5. Page numbers matching the lesson plan; footer/branding per house style.

## Templates and tools
- Mirror the designer's template or past deck (layout, fonts, colours, where title/picture/footer sit). See `output-format.md`.
- When adding pages to an existing deck in a design tool, duplicating an existing page keeps its formatting more reliably than creating new ones.
- Don't rely on one-click "generate design" features for content-specific slides — they tend to ignore content instructions. Build content first, then lay it out.

## Per-slide prompts
For each slide, a self-contained prompt for the designer's image/slide tool: subject, style line shared across the deck (keeps it consistent), the exact text that must appear (or "no text in image"), 16:9, and what to avoid (extra text, misspellings, copyrighted characters, inaccurate maps).
